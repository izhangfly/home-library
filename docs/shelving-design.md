# 上架算法设计

> 先把问题定义清楚，再写代码。这份文档是实现的依据，改算法前先改这里。

## 1. 为什么不是「装箱问题」

第一直觉会把它当成 bin packing（NP 难），但**真实图书馆不是这么排书的**：
书按索书号**全序**排列，一层排满了接着排下一层。既然顺序是给定的，
问题就从"任意分组"退化成"把一个有序序列切成连续段"——
这是**线性划分问题**，动态规划就能求最优解（O(n·k)），不需要启发式。

LeetCode 1105 *Filling Bookcase Shelves* 就是这个结构的最小版本。

**结论：保持索书号顺序 = 把 NP 难问题变成多项式问题。**
顺序不只是"图书馆的传统"，它是让这件事可算的前提。

## 2. 问题形式化

**输入**
- 书 `b ∈ B`：索书号 `call(b)`（全序）、书脊宽 `w(b)`、书高 `h(b)`、读者归属
- 层 `l ∈ L`：可用宽 `W(l)`、净空高 `H(l)`、离地高度 `z(l)`、所属书柜与平面坐标 `(x,y)`
- 人 `p ∈ P`：身高 → 舒适取书区间

**输出**：书 → 层的映射，以及从当前状态到目标状态的**移动清单**

**硬约束（违反 = 物理上做不到）**
1. `h(b) ≤ H(l)`：书比层高就是放不进去
2. `Σ w(b) ≤ W(l) - margin`：一层塞不下超过它宽度的书

**软目标（按权重排序）**
1. **顺序性**：同一区内，索书号相邻的书应当物理相邻（这是分类法的全部意义）
2. **可达性**：儿童书必须落在孩子够得着的高度
3. **最小扰动**：重排时移动的书越少越好
4. **紧凑性**：一个类别不应被拆散到很远的两个柜子
5. **留白**：预留生长空间，避免加一本书就要全屋重排

## 3. 分区（Zone）——解决"儿童书要放低"和"大开本放不下"

纯按索书号全局排序会把儿童书散布到各处。真实图书馆的做法是**分区**：
先划分若干独立区域，每区各自按索书号排序。

| 区 | 成员规则 | 位置偏好 |
|---|---|---|
| 儿童区 | 标签=儿童 / DDC 主类 J | 孩子舒适取书带内（低层） |
| 超高区 | `h(b)` 超过多数层净空 | 任何足够高的层，通常最底层 |
| 常规区 | 其余 | 成人舒适带优先 |

分区已经对应现有的 `TagZone` 模型，不用新造概念。

## 4. 可达性模型

身高 `H` 的人，舒适取书区间近似：

```
comfortable(H) = [0.25·H, 1.15·H] # 不用蹲下也不用踮脚
ideal(H) = [0.60·H, 1.00·H] # 视线高度，一眼扫过去就能找到
```

家里三个人（spec §1 给的身高）：

| 人 | 身高 | 舒适带 | 视线带 |
|---|---|---|---|
| 本人 | 183cm | 46–210cm | 110–183cm |
| 妈妈 | 160cm | 40–184cm | 96–160cm |
| 妹妹 | 140cm | 35–161cm | 84–140cm |

层的离地高度 `z(l)` 由该柜下方所有层的高度累加得出（已经有真实尺寸）。
儿童区的层必须满足 `z(l) ∈ comfortable(140cm)`，落在 `ideal` 内再加分。

## 5. 距离矩阵

移动成本和紧凑性都要用到"两层之间有多远"：

```
d(l1, l2) =
 同一柜: |z1 - z2| · kv # 只是弯腰/伸手
 同房间不同柜: euclid(xy1, xy2) + |z1-z2|·kv + Cbookcase
 不同房间: 上式 + Croom # 要走出房间
```

`(x, y)` 直接取自户型图（毫米），所以这个矩阵是**真实距离**，不是拍脑袋的权重。
`kv` 让垂直距离比水平距离便宜（伸手比走路容易），默认 0.3。

## 6. 留白策略（关键）

学术上这叫 **list labeling / library sorting problem**：
在有序数组里插入元素、让搬动次数最少。四十年的结论很朴素——
**别把空隙集中在末尾，要均匀撒开**。

实务上图书馆的经验值是**装到 70–75%**，剩下的不是"未来生长空间"，
而是日常上架、插入新书、多卷本对齐所必需的余量。

所以：
- 目标装填率 `fillTarget = 0.75`
- 每层按比例留白，而不是塞满一层再开下一层
- 这样插入一本新书通常只在本层内挪几本，不会触发跨层雪崩

## 7. 重排：最小扰动

重算出目标划分后，不能直接"照着摆"——那可能意味着搬动几百本书。

**做法：只重排受影响的连续区间。**
1. 找到第一处「当前放置 ≠ 目标放置」的位置
2. 从那里向后推进，直到某一层的空余能吸收掉位移量
3. 只对这段区间生成移动清单

**当必须跨层挪动时，优先挪小的那一组** —— 用户明确要求，也符合直觉：
把 3 本书挪到隔壁层，比把 40 本书整体平移便宜得多。
成本函数：`cost(move) = Σ_b d(from(b), to(b))`，在可行解里取最小。

## 8. 触发时机

重排是**建议**，不是自动执行。系统只在这些时候提示：
- 某层溢出（装不下了）
- 某区的书总宽超过该区已分配层的总宽
- 用户主动点「重新规划」

任何一次重排都要先给出预览：移动多少本、涉及哪些层、预计花多久。
**没有用户确认就不动任何 Placement 记录。**

## 10. 实现顺序

1. 距离矩阵 + 可达性（纯函数，可单测）
2. 分区定义与成员判定
3. 区内 DP 划分（含留白）
4. 差异对比 → 移动清单 + 成本
5. 预览 UI + 用户确认后批量执行
